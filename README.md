# Синхронизация чатов DSH

Плагин для DeepSeek Harness: **одни и те же диалоги на всех ваших компьютерах** — вместе с
прикреплёнными к ним файлами, настройками и инструкциями. Начали разговор на домашнем ПК,
открыли на рабочем и продолжили с того же места.

Репозиторий для обмена — ваш собственный приватный git-репозиторий (GitHub/GitLab) или просто
общая папка в облаке (Яндекс.Диск, OneDrive, сетевая папка). Никаких чужих серверов: данные
идут только между вашими компьютерами и вашим хранилищем.

---

## Как это выглядит

Страница **Настройки → Синхронизация чатов** отвечает на три вопроса без терминов:

* **Статус.** Цветной индикатор и одна фраза: «Всё синхронизировано», «Есть что отправить»,
  «Есть новые данные с других компьютеров», «Нужно ваше решение» или «Ошибка». Рядом —
  когда была последняя синхронизация и что именно изменилось.
* **Что синхронизировать.** Четыре переключателя с количеством файлов и объёмом: чаты,
  прикреплённые файлы, настройки и плагины, инструкции и навыки.
* **Компьютеры.** Список устройств с датами последней синхронизации и кнопка
  **«Добавить новый ПК»**, которая выдаёт код подключения и пошаговую инструкцию.

Кнопки: **Синхронизировать**, **Только отправить**, **Только получить**, **Обновить**.
Автосинхронизация по умолчанию включена (каждые 15 минут) и один раз догоняет изменения
вскоре после запуска Harness.

## Что синхронизируется

| Раздел | Что внутри | По умолчанию |
|---|---|---|
| Чаты | `$DSH_HOME/sessions/**` — вся история диалогов | вкл. |
| Прикреплённые файлы | `$DSH_HOME/attachments/**` — картинки и документы из чатов | вкл. |
| Настройки и плагины | `$DSH_HOME/cordis.patch.yml`, `profiles/<профиль>/cordis.patch.yml`, `profiles/<профиль>/package.json` | вкл. |
| Инструкции и навыки | `$DSH_HOME/AGENTS.md`, `$DSH_HOME/skills/**` | вкл. |

Никогда не покидают компьютер: `.credentials.yaml` и `.env` (секреты), `.anonymous-user-id`,
`logs/`, `cache/`, `dsh-runtimes/` (272 МБ бинарников Node/Python), `llm-deepseek/files-v3.json`
(истекающие серверные ссылки), `storages/session_projcache` (производный кэш).

## Как это работает

```text
<хранилище>/
  devices/<id>.json                карточка компьютера: имя, платформа, время
  snapshots/<id>/manifest.json     хэши содержимого и номер ревизии по каждому разделу
  snapshots/<id>/data/<раздел>/…   сама копия файлов
```

1. Компьютер **публикует** свою полную копию включённых разделов в `snapshots/<свой id>`.
2. Каждый компьютер пишет **только в свою папку**, поэтому два ПК физически не могут
   переписать файлы друг друга.
3. При синхронизации читаются манифесты остальных компьютеров, и по каждому файлу решается,
   чья версия новее (по хэшу содержимого и номеру ревизии).
4. Если вы меняли файл, а другой ПК — нет, применяется его версия. Если меняли оба —
   см. «Конфликты».
5. Затем публикуется своя версия, и всё это одним коммитом уезжает в репозиторий.

Логи чатов — это дописываемые файлы из независимых zstd-фреймов. Поэтому «одна версия
продолжает другую» распознаётся побайтово, без разбора формата: побеждает более длинная
версия, и никакого конфликта не возникает.

### Конфликты — без потери данных

Настоящий конфликт возможен только там, где один и тот же чат продолжили на двух ПК
одновременно. В этом случае:

* ваша версия **никогда** не перезаписывается;
* версия другого ПК сохраняется в `$DSH_HOME/sync/conflicts/`;
* на странице появляется карточка «Требуется внимание» с выбором: **оставить мою версию**
  или **взять версию с другого ПК**. Проигравшая версия тоже сохраняется файлом.

### Чаты из папок, которых нет на этом ПК

Чат привязан к папке, в которой он начат. Если на втором ПК такой папки нет, плагин:

1. использует папку, которую вы указали для неё на странице «нужна папка», либо
2. создаёт её, если это возможно (обычный случай, когда пути совпадают), либо
3. переносит чат в общую папку `~/Documents/DSH-Sync`, переписывает в заголовке чата путь
   на неё и регистрирует её как раздел — чат остаётся видимым и продолжается.
   Куда именно он переехал, видно на странице.

Пункт 2 работает только для путей **своего** типа: чат, начатый на Windows, на macOS
всегда попадает в общую папку (и наоборот). Иначе плагин создал бы на Mac папку с именем
вида `C:\Users\...`, а на Windows — каталог по пути `/Users/...` от текущего диска.

### Обновление плагина

Обновление ставится так же, как первая установка, но с одним отличием: сначала **удалите**
плагин на странице «Плагины» и только потом установите заново — иначе менеджер плагинов
может оставить уже загруженную версию из кэша. Состояние синхронизации при этом не теряется
(оно лежит в `$DSH_HOME/sync/state.json`), а после смены кода Host-части нужен перезапуск
Harness.

### Чего плагин не делает

* **Не удаляет данные.** Удаление чата на одном ПК не удаляется на других; чат вернётся
  при следующей синхронизации. Это осознанный выбор в пользу сохранности.
* **Не трогает открытый чат.** Если DSH держит чат открытым, его файл не заменяется —
  синхронизация отложит этот чат до следующего раза (в истории будет «отложено»).
* **Не синхронизирует список установленных плагинов как папки** — только `package.json`
  профиля; сами пакеты ставятся на каждом ПК отдельно.
* **Не берёт файлы больше 256 МБ** (такие перечисляются на странице как пропущенные).

## Установка на втором ПК

1. Установите плагин так же, как на этом ПК: **Настройки → Плагины → Установить** и укажите
   адрес этого пакета (например `github:ваше-имя/dsh-chat-sync` или путь к папке).
2. Откройте **Настройки → Синхронизация чатов** на первом ПК и нажмите **«Добавить новый ПК»**.
3. Скопируйте **код подключения**. Если хотите вставить один код и больше ничего —
   включите «Включить токен в код» (тогда код становится секретом).
4. На новом ПК откройте ту же страницу, нажмите **«Подключиться к существующей»**, вставьте код
   (и токен, если его нет в коде) и нажмите **«Подключиться»**.
5. Первая синхронизация запустится сразу: чаты с обоих ПК объединятся, ничего не потеряется.

### Настройка с нуля (первый ПК)

**Приватный git-репозиторий.** Вставьте токен доступа, нажмите **«Создать приватный
репозиторий»** — плагин создаст его сам. Либо создайте репозиторий руками и вставьте его
адрес, затем **«Проверить адрес»**. Токен нужен с правом `repo`
([создать токен](https://github.com/settings/tokens/new?scopes=repo&description=DSH%20Sync))
и хранится в защищённом хранилище Harness (`$DSH_HOME/.credentials.yaml`) — в общий
репозиторий он не попадает никогда.

**Общая папка.** Укажите папку, которая синхронизируется облачным сервисом. Ни аккаунтов,
ни токенов; истории версий не будет.

## Ограничения и мелочи, о которых стоит знать

* **Правки Host-части плагина требуют перезапуска Harness.** Node кэширует уже загруженные
  ES-модули на всё время работы процесса, поэтому изменённый файл не подхватится «на лету»;
  браузерная часть, наоборот, перезагружается без перезапуска. То же относится и к
  обновлению плагина: после переустановки перезапустите Harness.
* **Настройки применяются после перезапуска.** Если синхронизация принесла изменения в
  `cordis.patch.yml` или `package.json` профиля, страница об этом сообщит.
* **Установленные плагины нужно доустановить** на другом ПК (список приедет, пакеты — нет).
* **Имена приложенных файлов переносятся как есть.** Файл, чьё имя недопустимо в целевой
  системе (например, с `:` в имени на Windows), не скопируется; такой файл виден на странице
  как пропущенный, а сам чат синхронизируется.
* **Первый обмен большим архивом** может занять время: логи чатов и вложения перекачиваются
  целиком, дальше передаются только изменения.
* **Нужен установленный Git** для режима репозитория (в режиме папки не нужен).
* **`workspace.json` не синхронизируется как файл.** Этот документ меняется целиком и
  проверяется на согласованность; плагин добавляет чаты в разделы через работающий сервис
  Harness, а не правкой файла.

## Где что лежит

| Путь | Назначение |
|---|---|
| `$DSH_HOME/sync/state.json` | настройки плагина, базовые хэши, история |
| `$DSH_HOME/sync/store/` | локальная копия git-хранилища |
| `$DSH_HOME/sync/conflicts/` | сохранённые версии конфликтов и лишние копии чатов |
| `<хранилище>/` | общая копия: `devices/`, `snapshots/` |

## Устройство пакета

| Файл | Роль |
|---|---|
| `host-entry.js` | вход Host-половины: маршрут `/dsh-sync/api`, таймер автосинхронизации |
| `host/sync.js` | движок: сканирование, публикация, применение, конфликты |
| `host/store.js` | транспорт (git или папка) и layout хранилища |
| `host/git.js` | вызовы `git`, проверка и создание репозитория через API хостинга |
| `host/items.js` | каталог разделов и их корней |
| `host/zstd.js` | разбор контейнера логов чатов и перезапись заголовка |
| `host/session-paths.js` | правила каталогов чатов (порт из Harness) |
| `host/state.js`, `host/util.js` | состояние и файловые помощники |
| `host/workspace-file.js` | чтение списка папок из `workspace.json` |
| `host/http.js` | HTTP-интерфейс страницы |
| `client.js` | браузерная половина: страница в Настройках, мастер, конфликты |
| `locale/{ru,en,zh}.json` | название и описание в списке плагинов |

Страница не требует сторонних библиотек: только React из модульной таблицы Harness, тема —
через токены `--dsw-alias-*`.

## Проверка

Плагин проверялся инструментами, которые в этот пакет не входят (они остались в рабочей
папке разработки и в репозиторий не публикуются). Что именно проверялось, чтобы это можно
было повторить:

* разбор и перезапись заголовков настоящих логов чатов (контейнер из независимых
  zstd-фреймов);
* полный цикл движка на копии домашнего каталога: публикация, приём чужого чата,
  конфликт, разрешение конфликта, перенос чата из недоступной папки;
* обмен с настоящим git-репозиторием: коммит с чатами и настройками и его получение.

## English summary

A DeepSeek Harness plugin that keeps the same chats — and their attached files — available on
every computer, through the user's own private git repository or a shared cloud folder.
It publishes each computer's tree under its own device directory (so no two computers ever
write the same file), applies the newer version of each file by content hash, fast-forwards
append-only chat logs, and never overwrites or deletes anything: a genuine divergence is
reported in the Settings page with both versions preserved. Chats started in a folder that is
missing on this computer are moved to one shared folder with their recorded folder rewritten,
so they stay visible and continuable. The Settings page shows a plain-language status, a
per-section breakdown, the device list, and a connection code for adding a new computer.
